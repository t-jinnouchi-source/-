# 助成金作文（訓練必要性説明文）

## 0-0. なぜ作文の精度が効くのか（R7.4以降の審査構造）

**令和7年4月1日から、労働局は計画届の「確認・受理行為」を廃止し、受付のみとした。支給・不支給の審査は支給申請時に一括して行われる。**

この一点で、作文の位置づけが変わっている。

- 計画届の提出時に行われるのは、**記入漏れ・添付漏れの確認だけ**。作文の中身は見られていない。
- したがって **「計画届が受け付けられた＝作文がOK」ではない。**
- **作文の中身が審査されるのは、訓練を実施し終わった後（支給申請時）。**
- そこで表1①②④・表2に該当すると判定されると、**研修は実施済み・費用は支払済みで、もう直せない。**

> 昨年までの「計画届が通ったから今年も同じ書き方でよい」という判断は、**根拠にならない**。
> 受け付けられた作文は、審査を通った作文ではない。

**だからこの技能は、提出時ではなく起案時に潰しにいく。** Gate（§2）と機械チェック（§5）は、直せなくなる前に潰すための仕組み。

### 押さえる期限（3コース共通）

| 手続 | 期限 |
|---|---|
| 計画届の提出 | 訓練開始日の**6か月前から1か月前**まで |
| 支給申請 | 訓練終了日の**翌日から2か月以内** |
| 申請書類の保存 | 支給決定日の翌日から**5年間** |

訓練の実施内容・実施日時・場所・訓練時間数を変更する場合は**変更届**が必要（簡素化後も残っている）。

### 経費負担の取扱い（R6.11.5 明確化）

**訓練経費を申請事業主が全額負担していないと、経費助成の対象外になる。** 次は不支給。

- 教育訓練機関等から申請事業主への入金額と助成金支給額の合計が訓練経費と同額になる場合
- 訓練に関する広告宣伝業務（受講レビュー・感想・インタビュー等）の対価として金銭を受け取った場合
- 「研修の実施に際して費用負担がかからない」等の負担軽減の提案を受けて金銭を受け取った場合（営業協力費・協賛金など名目を問わない）
- その他、訓練等に付随して締結した契約に基づき金銭を受け取った場合

計画届に「**教育訓練機関と訓練契約を締結することとなった経緯**」欄がある（R6.11.5以降の届出日に適用）。負担軽減に係る説明資料を提供した場合はその資料の提出も必要。
**紹介手数料・営業協力費のスキームがある案件では、作文を書く前にここを確認する。**

## 0. この技能が解いている問題

UX-HATCH の作文は、**内容が悪くて直っているのではなく、書き始める前に決まっていなかったものが後から判明して作り直している**。
実際の改訂履歴（2026年度・シーホネンス6版／エスリード2版／4月案件9社）から抽出した手戻り原因は次の通り。

| # | 手戻りの原因 | 実例 | 本スキルでの封じ方 |
|---|---|---|---|
| 1 | **器（様式・欄・字数・フォント）が未確定のまま書いた** | シーホネンス 826字→478+379字→590字→566字→544字→583字 と6回作り直し。「550字が物理上限か目安か確認したい」と v3 時点でまだ未確定 | **Gate-A**。器が割れるまで本文を書かない |
| 2 | **制度改正を初稿で反映していない** | R8.8.3改正（表1①②注記新設）の4日後に書いた初稿が未反映。同日中に v3 で全面改稿 | **Gate-B**。起案日 vs 直近改正日を必ず突き合わせ |
| 3 | **様式の付番変更に気づかず、存在しない欄に書いた** | v2 は「様式第1-1号19欄」に478字書いたが、R8.4版様式に19欄は存在しない | **Gate-A** の様式実物確認 |
| 4 | **表1④（マニュアル・基準の作成／改善）接触語のリグレッション** | v3 で「自社で定め運用し続ける力」「体制を自社に定着させ」を全削除 → 最終docxで「業務の標準化を図ります」が復活 | **禁止語台帳を案件ファイルに持ち、全版に適用**＋機械チェック |
| 5 | **構造要件が最終版で欠落** | 受発注管理の最終版で「中でも管理部門の担当者は〜従事しています」（0303ヘ(ロ)②）が消え、「そのため同担当者には」だけ残り主語が宙に浮いた | 機械チェックの**構造判定**を最終版にも必ずかける |
| 6 | **他社案件との重複チェックがない** | 4月案件（sizzle／グリーンツリー／ETERNAL BEAUTY）は講座名も本文骨格も完全同一 | 機械チェックの**案件間重複**（同一実施機関の横断チェック） |
| 7 | **実データ／仮題の方針がブレる** | メガソフト3講座目「実際の業務データを用いた分析や集計を実践し」は表2-7直撃。シーホネンスは遮断文を置く→置かないで方針転換 | **仮題ルール**を固定（§4-3） |
| 8 | **連年・連続講座の書き方に判断基準がない** | シーホネンス＝前年訓練を名指ししない／エスリード＝「前年度の訓練で〜身につきましたが」と明示 → さらに0822修正版で削除 | `references/05_renzoku.md` の判定表 |
| 9 | **先方の実呼称を最後に反映している** | 「粒度」→「細かさ」、「作業日報」→「報告書」、「是正処置記録」→「日々の不良事項やエラー」を最終版で一斉置換 | **Gate-C**。起案前に語彙表を埋める |
| 10 | **カリキュラム表と作文が別プロセス** | 「カリキュラム⑨の講座名が昨年と文字面一致」を作文側で発見 | Phase 1 で**カリキュラム表を先に固定**し、作文は鍵括弧で引用 |

## 1. 絶対ルール

1. **Gate（§2）を通さずに本文を書かない。** 器が割れないときは仮の器を宣言し、`【器未確定】` を成果物の先頭に書く。黙って書くのは禁止。
2. **機械チェック（§5）を通さずに納品しない。** 「チェック済み」と文章で書くのは証拠にならない。`check_sakubun.py` の出力を添付する。
3. **一度潰した表現は復活させない。** 案件ごとに `禁止語台帳.md` を作り、版が変わっても必ず引き継ぐ。最終版・清書版にも同じチェックをかける。
4. **確定していない事実を書かない。** 認証名（ISO等）・製品仕様・拠点構成・人数の内訳は、一次資料で確認できたものだけ。実地調査で訂正を求められる余地を残さない。
5. **作文は「訓練が対象労働者の職務に直接関連する専門的な知識及び技能か」の一点を論証する文書である。** 研修の魅力を伝える文書ではない。営業資料の語彙を持ち込まない。

## 2. Gate（起案前に必ず埋める4点）

**4点すべてが埋まるまで本文を1文字も書かない。** 埋まらない項目は「誰に、いつまでに、何を聞くか」を確定してから仮置きで進める。

### Gate-A｜器を割る
| 項目 | 確認先 | 埋まっていないと起きること |
|---|---|---|
| コース名（事業展開等リスキリング支援／人材育成支援 等） | 社労士 | 参照する支給要領の条項ごと変わる |
| **現行様式の版とファイル実物** | 社労士／労働局サイト | 存在しない欄に書く（v2の実例） |
| **貼り付ける欄の正式名称と欄番号** | 様式実物 | 「19欄」「様式第2号」など旧称で会話が噛み合わない |
| **記入枠の物理上限字数**（フォントサイズ別） | 様式実物を実測 | 6回作り直し（シーホネンスの実例） |
| 別紙・備考欄の可否と役割分担 | 社労士 | 段落2・3の格納先が決まらない |

> **実測の目安（R8.4版 様式第1-3号 4欄）**：8.5pt で約603字／9pt で約504字（枠の物理上限）。
> ただし**実際に提出された実績は 406字・451字**（2026年6月・東京労働局・提出控えPDFより実測）。
> **枠の上限と、実際に社労士が入れている字数は違う。両方を Gate-A で確認する。**

### Gate-B｜制度の鮮度を確認する
- 直近の支給要領改正日・パンフレット改訂日を確認し、**起案日との前後関係**を書き残す。
- **経過措置**を必ず確認する。事業内訓練では、経費に係る契約・申込・発注のいずれか1つが改正日以前なら旧基準で審査される場合がある（附則1402ロ）。**UX-HATCHと先方の契約日／申込日を最初に確認する。**
- 直近の重要改正（2026年8月3日）：DX・GX関連訓練であっても「職業人として共通して必要となるもの」は対象外と明記された。→ **「DX研修だから対象」というルートは閉じている。**

### Gate-C｜先方の実呼称を取る
先方が実際に使っている帳票名・工程名・部署名を**起案前に**埋める。ここを飛ばすと最終版で一斉置換が発生する。
→ `references/04_hearing.md` の語彙表を使う。

### Gate-D｜連年・重複を洗う
- 同一事業主の**過去の計画届**（前年度・同年度別コース）を入手し、使用済み表現を抽出する。
- 同一受講者が年度内に何回目か（年度内3回まで）。
- 同時に出す他部門・他社案件の作文一覧（横断重複チェックの対象）。
- → 判定は `references/05_renzoku.md`。

## 4. 本文の型

### 4-1. 支給要領0303ヘ(ロ)の3段構成 ＝ 第1段落に文単位で充当する

第1段落は**4文**で固定する。文の役割を崩さない。

| 文 | 役割 | 主語 | 書き方 |
|---|---|---|---|
| 第1文 | ①事業主が進めるDX化の取組 | **当社** | 「当社は〜として、〇〇を電子データとして整え、△△に生成AIを用いる運用へ移行しています。」 |
| 第2文 | ②これに関連する業務に従事させる対象労働者 | **人（担当者）** | 「中でも〇〇部門の担当者は、△△の作成に従事しています。」 |
| 第3文 | 生じている事象（課題） | 事象 | 「しかし、〜のため、〜という状態になっています。」 |
| 第4文 | ③その上で必要な専門的な知識及び技能 | 技能 | 「そのため同担当者には、〜する専門的な知識及び技能の習得が必要です。」 |

> **②を飛ばすと表1①で落ちる。** 実際に最終版で②が欠落し、第4文の「同担当者」が宙に浮いた事故が起きている。機械チェックで必ず検出する。

### 4-2. 第2段落＝訓練内容、第3段落＝訓練後

- **第2段落**：カリキュラム項目を**漏れなく**収容する。前半だけ書いて後半（最終回）を落とすと、総訓練時間と作文の記述範囲がずれ、落とされた時間分が否認される導線になる。
  - 文型：「本研修では、仮題の〇〇を題材として、〜を学びます。／あわせて、〜を習得します。／さらに、〜に関する専門的な知識及び技能を身につけます。」
  - **講座番号・回数・時間数は本文に書かない**（カリキュラム表・時間割と食い違うと修正になる）。
- **第3段落**：「結果として／これにより」→ 何が揃うか → 部門の業務にどう活きるか → DX着地。
  - **成果を約束しない**（「〜を実現します」「競争力を強化します」は成果約束語。§4-4）。

### 4-3. 仮題ルール（固定）

- 演習の題材は**すべて仮題**。対象物の側に冠する：「**仮題の**施設情報」「**仮題の**作業標準」「**仮題の**業務手順」。
- 「実際の業務データを用いて」「当社の〜の流れに沿って」は**書かない**（表2-7 就労の場での訓練／表1④に直撃）。
- 否定形の遮断文（「自社の実帳票は扱いません」）は**任意**。字数が苦しいときは肯定形の「仮題の〇〇」だけで足りる。ただし**どちらの方針で書いたかを納品メモに明記**し、版をまたいで揺らさない。

### 4-4. 禁止語（全文で0件にする）

4カテゴリ。詳細と全リストは `references/03_ng-words.md`。

| カテゴリ | 例 | 理由 |
|---|---|---|
| **R8.8.3 対象外語** | AIリテラシー／情報リテラシー／ITリテラシー／意識の向上／基礎知識／概論／入門／事例紹介／操作方法 | 「職業人として共通して必要となるもの」に読まれる |
| **表1④ 接触語** | 標準化／マニュアルの作成／基準を自社で定め／体制を定着させ／規程の整備／業務改善の指導／外注に頼らず自社で | 通常の事業活動・マニュアル作成・経営改善指導に読まれる |
| **成果約束語** | 競争力を強化します／生産性向上を実現します／成約率の向上／コスト削減が実現し／〇%削減 | 訓練の効果として保証できない |
| **連年重複語** | 前年度の当該事業主の作文から機械抽出した語（案件ごとに可変） | 同一・類似訓練の重複受講に読まれる |

**さらに、旧型作文で頻出していた次の語も使わない**（2026年4月案件で多用。R8.8.3以降は危険）：
属人化／属人的／個人の経験や勘に依存／習得します（体言止めの羅列）／不可欠です／急務です／創出された時間／セキュリティリテラシー／ハルシネーション／機密情報の取り扱い等の情報リテラシー

### 4-5. 語彙のレベル

**審査官が読む文書である。** 社内用語・コンサル用語を持ち込まない。実際に最終版で置換された例：

| 使わない | 使う | 備考 |
|---|---|---|
| 粒度 | 細かさ／どこまで書くか | |
| 工程モデル | 業務の工程／進め方 | ただしカリキュラム表の正式項目名なら引用可 |
| 作業日報・是正処置記録 | 先方の実呼称（例：報告書／日々の不良事項やエラー） | Gate-C で取る |
| 三項目（漢数字） | 3項目 | 表記統一。同一文書内で混在させない |
| ソリューション／リスキリング／DX人材 | 平語に開く | |

## 5. 機械チェック（納品前に必ず実行）

```bash
python3 .claude/skills/josei-sakubun/scripts/check_sakubun.py \
  --file 作文_営業.txt \
  --min 450 --max 583 \
  --ng-extra 案件固有禁止語.txt \
  --cross 作文_工場.txt 作文_業務.txt
```

出力される判定：

| 判定項目 | 内容 |
|---|---|
| `LENGTH` | 改行・空白を除く実字数が器の範囲に収まっているか |
| `STRUCTURE` | 0303ヘ(ロ)①②③が第1段落に揃っているか（②の対象労働者の特定が最頻の欠落） |
| `NG_R8` | R8.8.3対象外語 |
| `NG_HYO1_4` | 表1④接触語 |
| `NG_PROMISE` | 成果約束語 |
| `NG_LEGACY` | 旧型作文の頻出語 |
| `NG_EXTRA` | 案件固有（前年度作文からの抽出語） |
| `JARGON` | 平語に開くべき語 |
| `KARI` | 演習題材に「仮題」が冠されているか／実データ使用の記述がないか |
| `FOREIGN_OBJ` | 他部門の対象物語が混入していないか（部門別に複数本出すときの本丸） |
| `CROSS` | 他部門・他案件の作文との共通表現（15字以上の一致）。`--cross-mode client` で別会社への使い回しを検出 |
| `NUMERIC` | 人数・時間数・回数・講座番号が本文に混入していないか |

**全項目 PASS まで戻る。** 1つでも FAIL の状態で納品しない。

## 6. 納品パッケージ（社労士・社内に渡す形）

作文本文だけを渡さない。次の5点をセットにする。

1. **本文**（版番号・作成日・貼り付け先の欄名を明記）
2. **器の記録**：様式版／欄名／実字数／想定フォントサイズ／別紙の有無
3. **判断の記録**：連年をどう扱ったか、仮題の遮断文を置いたか置かなかったか、区分の選択案とその理由
4. **機械チェック出力**（コピペではなく実行結果）
5. **確認依頼リスト**：確度が低く社労士・労働局に確認が要る事項を箇条書き（例：区分の選択肢名、記入枠の物理上限、契約日と経過措置の可否）

## 7. レビュー依頼のとき（既存作文を見る場合）

「この作文見て」と言われたら、**書き直す前に Gate を逆算で埋める**。器が分からないまま添削すると字数の作り直しが起きる。

1. どの様式のどの欄に貼るか／字数上限はいくらか を先に聞く
2. 機械チェックを実行し、FAIL 項目を提示する
3. FAIL 項目ごとに「なぜ危ないか（どの表・どの条項に接触するか）」と「置換案」をセットで出す
4. severity（high／medium／low）を付ける。high＝不支給・否認に直結、medium＝疑義照会を招く、low＝体裁
