# 連年・複数講座・複数部門の書き分け

「同一・類似訓練の重複受講」（表1-4⑦）に読まれないための判定。
**実案件で判断が割れた論点なので、ここで基準を固定する。**

---

## 1. 判定表｜前の訓練に言及するか

| 状況 | 前の訓練に言及 | 理由 | 実例 |
|---|---|---|---|
| **前年度・別テーマ・同一受講者が含まれる** | **しない** | 冒頭で前年度訓練を名指しすると、表1-4⑦の重複受講を審査側に想起させる。また「前年度は基準を整え」と書くと裏付けのない事実の主張になる | シーホネンス（前年＝情報セキュリティ研修） |
| **同一年度・連続講座（P1→P2→P3）** | **する。ただし事実として** | 段階が上がる訓練であることが、別訓練である最大の根拠になる | エスリード（P1基礎定着編→P2応用編） |
| **前年度・同一テーマの続き** | **要検討。原則しない** | 同一テーマの連年は最も危険。テーマ自体をずらすことを先に検討する | — |

### 言及する場合の書き方

前の訓練で**何ができるようになったか**と、**なぜそれでは足りないか**を、事実として1文で書く。

> 前年度の訓練で1件ごとに書き起こす手順は身につきましたが、その文案は再び使える形で残らず、規程の改定ごとに全件を書き起こし直します。

- 前の訓練名を書かない（「前年度の訓練で」で足りる）
- 前の訓練を否定しない（「不十分だった」と書くと前年の支給の妥当性に触れる）
- **今回の技能が前回の技能と別物であること**が、対象物と動作で分かるように書く

### 言及しない場合の一貫性の担保

前年と同じ文体・同じ構成・同じ経営方針の言葉（例：「第三の創業」）を使うことで、**同一社の書類として自然に読める**状態を作る。連続性は文体で示し、別訓練であることは内容で示す。

> ただし**3本以上を同時に出す場合は、経営方針の言葉を全本に入れるか全本から抜くかを揃える。**
> シーホネンスでは最終版で営業だけ「第三の創業」が残り、工場・業務から消えた。並置されたときに不自然になる。

## 2. 別訓練であることを示す3点セット

作文に**明示的に書かなくてよい**が、口頭で問われたときに即答できるよう納品メモに残す。

| # | 示すもの | 書き方 |
|---|---|---|
| ① | **訓練対象が違う** | 扱う対象物（帳票・記録・情報）が前回と一語も重ならない |
| ② | **課題の型が違う** | 前回＝◯◯、今回＝△△ と別の現象を書く |
| ③ | **着地の指標が違う** | 前回＝◯◯、今回＝△△ と別の指標に着地する |

## 3. 区分の選び方

### 13欄（訓練の種類）
- 新規事業・新分野進出の要素がなければ「企業内のDX化に伴い実施する訓練」で据え置き。
- 「事業展開」を混ぜると区分が不整合になる。

### 17欄（デジタル人材の育成区分）
**前年と同じ区分を選ぶと「同じ区分・同じ実施機関・同じ受講者」の三点一致になり、重複受講の疑義を自分から作る。**

| 訓練の中身 | 推奨区分 |
|---|---|
| 業務プロセスの手順設計・記述・判定・検証 | ビジネスアーキテクト関係 |
| データの集計・分析・可視化が主 | データサイエンス関係 |
| セキュリティが主題（連年は避ける） | サイバーセキュリティ関係 |
| 上記に当てはまらない | その他DX関係（※定義で「DXリテラシーを除く」と明記されている点に注意） |

> **区分の正式名称は現行様式で確認する。** 選択肢名は年度で変わる。判断は労働局照会が安全。

## 4. 複数部門を同時に出すとき（3本以上）

3本を並べて読まれる前提。**使い回しに見えた時点で疑義になる。**

### 分離する5つの軸

| 軸 | やること | 検出 |
|---|---|---|
| **対象物語** | 部門ごとに扱う帳票・対象物を排他にする。1語も混入させない | `CROSS` |
| **課題語** | 部門ごとに別の現象を書く。「担当者ごとにバラつく→揃える」を3本で使わない | 手動 |
| **書き出し位置** | 第1文の主語となる対象を部門ごとに変える | 手動 |
| **接続句** | 「加えて／結果として」「あわせて／これにより」「さらに／その結果」を本数で振り分ける | 手動 |
| **着地の指標** | 部門ごとに別の指標にする | 手動 |

### 対象物語の排他リスト（例：医療機器メーカー3部門）

| 部門 | 使ってよい語 |
|---|---|
| 営業 | 施設情報／施設種別／病床数／改築計画／訪問前ブリーフ／提案書／比較表／想定質問／受注・失注データ／商談記録 |
| 工場 | 作業報告／製造記録／作業標準／工程写真／不具合報告／記録様式／図面 |
| 業務 | 注文書／納品書／請求書／在庫の引き当て／納期回答／突合／業務手順／台帳 |

**この表を案件ごとに作り、`check_sakubun.py --cross` に渡す。**

### 全部門合同回がある場合

3本が同じ枠組みで書かれていると「全社一律の共通研修」と読まれ、その時間が表1②で否認される。
**部門固有の対象物に紐づけて書き分ける。**

| 部門 | 合同回の書き方 |
|---|---|
| 営業 | 提案資料を社外へ示す前の記載内容と出典の検証／取引先から届く情報の取扱いに関する照会への回答文書の作成 |
| 工場 | つくった草案が記録として成立するかを確かめる手順／審査機関から届く記録の提供範囲に関する照会への回答文書の作成 |
| 業務 | 集計結果と帳票の突合による検証／取引先の年次の確認事項への回答文書の作成 |

**「情報セキュリティ研修」という語を作文に一度も使わない。**

## 5. 他社案件との重複（同一実施機関リスク）

**UX-HATCH が同時期に複数社の計画届を出す場合、同一実施機関として横断的に見られる可能性がある。**

2026年4月案件では、3社（sizzle／グリーンツリー／ETERNAL BEAUTY GLOBAL）の講座名が完全に同一で、本文の骨格も同一だった：

```
リサーチ・ドキュメント作成の生産性を飛躍させる 生成AI活用基礎研修
オフィスツール連携による「業務自動化」実践研修
現場主導でDXを実現する！プログラミング不要のシステム構築研修
```

### 対応

- **講座名は業種・部門に紐づけて変える。** テンプレ名を社名だけ変えて使い回さない。
- **第1段落は必ず個社固有にする。** 業界一般論から書き出すと他社と同じ文章になる。
- 同時期に出す他社案件の作文を `--cross` に渡し、15字以上の一致を潰す。
- パッケージ商品として同一カリキュラムを提供すること自体は問題ない。**作文が同一なのが問題。**
