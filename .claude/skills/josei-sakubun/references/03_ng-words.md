# 禁止語・危険語

`scripts/check_sakubun.py` はこのファイルの語を検出する。**リストを更新したらスクリプト側の定義も更新すること**（スクリプトが正、本ファイルは理由の記録）。

---

## A. R8.8.3 対象外語（severity: high）

**理由**：令和8年8月3日改正で、パンフレット P28 表1①②に「DX・GX化に関する訓練であっても対象外となります」の注記が新設された。「職業人として共通して必要となるもの」と読まれる語は使えない。

```
AIリテラシー / 情報リテラシー / ITリテラシー / デジタルリテラシー / リテラシー
意識の向上 / 意識向上 / 意識改革 / 社員一人ひとりの意識
基礎知識 / 基本知識 / 基礎的な知識 / 基本概念
概論 / 入門 / 初歩 / 初歩的 / 事例紹介 / 活用事例の紹介
操作方法 / 基本操作 / ツールの使い方
生成AIとは / DXとは / DX概論
一般教養 / ビジネスマナー / コンプライアンス研修
```

**回避の考え方**：知識そのものではなく、**対象労働者の職務に直結する判断行為**を書く。
- ✗ 生成AIの基本概念やハルシネーションの特性を正しく理解し
- ✅ 生成AIが示した内容を営業の判断基準に照らして確かめる

## B. 表1④ 接触語（severity: high）

**理由**：表1④は「通常の事業活動として遂行されるもの」を対象外とする。例①＝コンサルタントによる経営改善の指導、例②＝品質管理・マニュアル等の作成や改善。
**自社の基準・規程・マニュアル・体制を「作る／整える／定着させる」と読める語は、訓練ではなく事業活動になる。**

```
標準化 / 業務の標準化 / 標準化を図る
マニュアルの作成 / 手順書の整備 / 規程の整備 / 社内基準の策定
基準を自社で定め / 判定の基準を定め / ルールを定め
体制を定着させ / 体制を構築 / 体制を確立 / 仕組みを構築
運用し続ける力 / 見直し続ける体制
外注に頼らず自社で / 内製化 / 自社で組み立て
業務改善の指導 / 業務プロセスの改善 / 経営改善
情報基盤の構築 / 一元管理の仕組み
```

**回避の考え方**：**成果物ではなく、人の判断行為**に限定する。
- ✗ 記録の判定基準を自社で定め、手順として書き残し運用し続ける力
- ✅ 記載事項を読み取り、記載すべき要素の細かさを判定して書き分ける専門的な知識及び技能
- ✗ 手順を見直し続ける体制を自社に定着させ
- ✅ 手順の記述を見直す方法を身につけ
- ✗ 業務手順書の草案を作成し、修正する
- ✅ 仮題の業務手順における記述の細かさの判定と草案の作成

> **注意**：この語群は**リグレッションが起きやすい**。実際に v3 で全削除した「標準化」系が最終版で「AI活用を通じた業務の標準化を図ります」として復活した事故がある。**最終版・清書版にも必ず同じチェックをかける。**

## C. 成果約束語（severity: medium）

**理由**：訓練の効果として保証できない。支給申請時に実績を問われる余地を作る。

```
競争力を強化します / 競争力の強化
生産性向上を実現します / 生産性が抜本的に高まります
成約率の向上 / 受注率の向上 / 売上の向上
コスト削減が実現 / 採用コストの大幅な削減
劇的に削減 / 大幅に短縮 / 半減 / 飛躍
〇%削減 / 〇割削減 （数値目標全般）
創出された時間 / 創出した時間を〜に充てる
期待できます / 実現します（成果を目的語に取る場合）
```

**回避の考え方**：「〜できる知識及び技能を身につけ、〔部門〕の業務に活かします」で止める。

## D. 旧型頻出語（severity: medium）

**理由**：2026年4月案件の作文で多用されていた語。R8.8.3以降は表1①②に接触するか、審査上の印象を悪くする。
また、**過去の計画届に同じ語が並ぶと連年重複の判定材料になる**。

```
属人化 / 属人的 / 個人の経験や勘に依存 / 個人のセンスに頼らない
不可欠です / 急務です・急務となっています / 生命線です / 鍵を握っています / 革新的 / 底上げ
ハルシネーション / セキュリティリテラシー / 機密情報の取り扱い等の情報リテラシー
情報漏洩を防ぐ / 情報漏えいが許されない / セキュリティ強化 / 防御力
顧客や取引先の信頼を守り / 事業の継続性を確保
ノーコード / RAG / プロンプト（本文に技術用語として置く場合）
超速 / 劇的 / 抜本的 / 飛躍させる
```

> `ノーコード` `RAG` `プロンプト` は、**カリキュラム表の正式項目名として引用する場合のみ可**。作文の地の文で使わない。

## E. 平語に開くべき語（severity: low、`JARGON` で検出）

**理由**：審査官が読む文書。社内語・コンサル語は伝わらないか、誤読される。

| 使わない | 使う |
|---|---|
| 粒度 | 細かさ／どこまで書くか |
| 工程モデル | 業務の工程／進め方（※カリキュラム表の正式項目名なら引用可） |
| ソリューション | 解決／手段 |
| リスキリング | （コース名としてのみ可。本文では使わない） |
| DX人材 | （17欄の区分名としてのみ可） |
| アセット | 資産 |
| ステークホルダー | 関係者／取引先 |
| ボトルネック | 滞り／詰まり |
| ドキュメント | 文書／書類 |
| フォーマット | 様式／書式 |
| オペレーション | 業務／作業 |
| 三項目（漢数字） | 3項目（表記統一。同一文書内で混在させない） |

## F. 案件固有禁止語（severity: high、`--ng-extra` で渡す）

**作り方**：

1. 同一事業主の**過去の計画届 PDF** を入手し、作文部分をテキスト化する。
2. 次を抽出して `案件固有禁止語.txt`（1行1語）に落とす。
   - 前年の作文に出てくる**特徴的な連語**（例：「顧客や取引先の信頼を守り」「社員一人ひとり」「防御力」）
   - 前年の**訓練名・カリキュラム項目名**に含まれる語
   - 前年の**着地の言い回し**
3. 全版のチェックで `--ng-extra` に渡す。

**実例（シーホネンス／前年＝情報セキュリティ研修）**
```
顧客や取引先の信頼を守り
情報漏えいが許されない
セキュリティ強化は不可欠
防御力
社員一人ひとり
事業の継続性を確保
情報漏洩の原因と実例
```

## G. 本文に書いてはいけない情報（`NUMERIC` で検出）

| 項目 | 理由 | 正しい記載先 |
|---|---|---|
| 受講人数 | 本文と食い違うと修正 | 様式第1-1号 7欄・17欄 |
| 訓練時間数・回数 | 時間割との突合で修正 | カリキュラム表・時間割 |
| 講座番号（第1回、①②） | カリキュラム表との突合で修正 | カリキュラム表 |
| 未確認の認証名（ISO等） | 実地調査で訂正を求められる | 書かない |
| 未確認の製品仕様・拠点構成 | 同上 | 書かない |
| 沿革の年数（「創業68年」等） | 年をまたぐとずれる | 書かない |
